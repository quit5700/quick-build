# Minecraft 26.x 移植与构建记录

## SavedData 文件名与版本 API

- 1.21.8、1.21.11 的 `SavedDataType` 名称参数是直接用于磁盘文件名的字符串，必须使用不含命名空间冒号的扁平 ID；禁止传入 `ResourceLocation.toString()`。
- 26.1.2、26.2 的对应构造函数接收 `ResourceLocation`（资源位置）对象，可由 Minecraft 正确分离命名空间与路径，不应为了统一代码退回字符串拼接。
- Windows 文件名检查不能只扫描已生成文件，因为非法路径会在文件创建前失败；应同时覆盖运行时 ID 生成逻辑并测试 `<>:\"/\\|?*` 等非法字符。

## 已验证配置

- Minecraft（我的世界）：`26.2`
- Java（爪哇）：`25`
- Fabric Loader（Fabric 模组加载器）：`0.19.3`
- Fabric API（Fabric 应用程序接口）：`0.154.0+26.2`
- Fabric Loom（Fabric 构建插件）：`1.15.5`
- Mojang Official Mappings（Mojang 官方命名映射）；不声明 Yarn Mappings（Yarn 命名映射）依赖。
- Gradle Wrapper（Gradle 包装器）：`9.2.1`

## 成功方法

1. 26.x 只声明实际使用的 Fabric API 子模块，避免完整 Fabric API 的 datagen（数据生成）转换问题。
2. 中文项目路径下，把测试 class（类）输出同步到 `%TEMP%/quick-build-test/26.2` 英文目录再运行 JUnit（Java 单元测试）。
3. 所有旧物品与方块继续使用原命名空间；合并只改变 Fabric 模组容器，不改变注册 ID。
4. 26.2 GUI 使用 `GuiGraphicsExtractor.item(ItemStack, x, y)` 绘制物品，不使用旧版渲染方法。
5. 自定义 Screen（界面）必须按实际逻辑分辨率动态计算每页按钮数，所有裁剪和内容区域必须保证宽高大于 `0`；过长按钮文字要先截断。
6. 红石中继读取邻居信号时必须抑制自身输出，避免通过实心导体重新读回自身信号并永久通电。
7. `useOn`（对方块使用）会在按住右键时重复触发；两点式工具必须在服务端增加短冷却，并在完成后同时清除业务数据和 Custom Model Data（自定义模型数据）。
8. 删除网络边后必须用删除前的完整连通分量刷新设备；只刷新删除后的单侧或依赖运行时跟踪集合会留下错误输出状态。
9. 26.2 的 BlockItem（方块物品）悬停名称需要 `item.<namespace>.<path>` 翻译键；只提供 `block.*` 会在设置界面显示原始翻译键。
10. 跨客户端/服务端的工具状态必须提供查询与恢复消息；不能只依赖客户端静态字段记住服务端会话。
11. 感应器到感应器的新连接必须先验证同轴、中间 1 至 10 格为无障碍空间且区块已加载；`minecraft:light`（原版无形光源）与空气都不算阻挡；删除已有连接必须先于几何验证，避免线路被遮挡后无法断开。
12. 结构工具用 `setBlock`（设置方块）搬运自定义方块时，不能依赖普通玩家放置回调同步附属数据；应保存数据快照，在方块落地验证后事务式替换坐标并主动同步客户端。
13. 定向红石方块的 `getSignal`（获取信号）方向表示“接收方指向当前信号源”的查询方向，不是信号从当前方块发出的物理方向；物理输入/输出面与查询方向的换算必须由可测试策略统一完成。
14. 会读取并输出红石粉信号的双向设备必须比较相邻红石粉强度与自身当前输出；相邻强度不高于自身输出时应视为自身回声，不能再次作为外部输入。
15. 红石输出模式或输出状态改变时必须通知所有可能残留旧电量的邻面重新计算；不能因为某一面当前被定义为输入面就跳过清除通知。
16. 延时开关模型未旋转时，`FACING`（朝向）指向北侧箭尾，箭头尖端位于南侧；两种模式都只从箭尾输入。定向模式只从箭头输出，五面模式从其余五面输出，不得动态扫描或持久化活动输入面。
17. 局部白昼实体亮度存在两套版本架构：26.1.2、26.2 与 1.21.11 使用实体光照入口、方块实体渲染状态入口，以及箱子和可刷方块的最终覆盖入口；1.21.8 及更早版本使用实体光照入口与 `LevelRenderer.getLightColor`（世界渲染器取光）两个重载，后者可同时覆盖普通方块实体、双箱亮度合并和可疑方块刷取物品。两套方案都只在客户端局部白昼快照范围内生效，不能影响原版无形光源模式。
18. 可变恒亮灯的原版无形光源使用 `VariableLightTaskState`（可变灯任务状态）持久队列；跨版本移植必须在服务器结束 Tick 时遍历全部世界并调用 `VariableLightTaskState.get(world).tick(world)`。只注册旧的 `ConstantLightTaskQueue.tick()` 会让任务能够保存却永远不执行，画面只剩灯自身约 14 格自然衰减。
19. 可变恒亮灯的大范围重设必须把当前安装任务排在历史清理之前，旧存档规范化时也必须保持相同顺序；清理函数通过当前有效源覆盖判断保留新范围。Minecraft 1.20.x 的局部白昼还需覆盖 Fabric Indigo 的 `ChunkRenderInfo` 亮度/环境遮蔽缓存；Sodium 0.5.x 使用 `me.jellysquid` 旧命名空间，不能复用后续 `net.caffeinemc` 目标名。
20. Minecraft 1.20.x 移植客户端局部白昼时，除生成 `quick_build.client.mixins.json` 和兼容类外，必须在 `fabric.mod.json` 的 `mixins` 数组中注册该配置；否则 Fabric Loader 不报错但所有渲染入口均不会加载。诊断已证明旧版单次快照正常到达，周期补发不是根因且会增加无关资源占用，禁止再次采用。通电灯从旧存档/区块恢复时，登记缺失必须补建安装任务，登记完全一致则不得重复排队。
21. 可变恒亮灯配置不能把半径、间隔和模式组合成 `1000+` 的原版容器按钮编号；远程客机经过网络协议后会截断。全版本必须使用 `0～73` 分项传值、`74` 服务端一次应用的单字节安全协议，并保留覆盖全部取值且断言编号不超过 `127` 的回归测试。

## 已尝试失败

- 不要在 26.x 改用完整 Fabric API 总包参与编译。
- 不要让普通 JUnit 直接实例化需要 Minecraft 客户端运行环境的 GUI 或提供器类。
- 不要把旧版 GUI 的物品绘制方法直接搬到 26.2。
- 不要在放置、首次 Tick 或区块加载路径重新调用感应器自动配对。
- 不要只根据构建成功判断红石功能已经在游戏中验证。
- 不要通过修改光柱渲染器修复寻路方块移动后的旧光柱；光柱只应继续读取已同步的线路节点坐标。
- 不要在纯 Java 轻量测试中直接引用 Minecraft `Direction`（方向）类；当前 ASCII（英文路径）测试运行时不加载游戏类，应以通用方向枚举验证同一策略。
- 不要把感应器几何限制应用到感应器与开关/发射器的普通网络连接；该限制只用于感应器到感应器的新增连接。
- 不要只在 `RECORDED`（已记录）客户端阶段接受移动投影快捷键；服务器已经记录成功而客户端阶段滞留时也必须能够恢复。
- 不要对创造页或设置页做全局名称排序；需要连续展示的编号系列和颜色系列必须使用显式分组顺序。
- 不要把 `getSignal` 的查询方向直接当作物理输出方向；`test8` 已证明这种做法会让输入面输出并与相邻感应器形成永久自反馈。
- 不要只修延时开关的方向公式；`test9` 仍因跳过输入面邻居刷新、感应器读取自己供电的红石粉而产生锁存。
- 不要把定向模式和五面模式设成不同输入面；两者都固定箭尾输入。不要让只验证输出数量的轻量测试替代模型几何和六个物理面的完整真值表。
- 不要再使用 `test11` 的“五面模式从箭头输入并排除箭头输出”方案；该方案把五面规则整体反转。
- 不要用严格 `isAir`（是否为空气）判断感应线遮挡；恒亮灯会放置无形 `minecraft:light`，它没有碰撞且必须允许感应线通过。
- 不要把 26.x/1.21.11 的方块实体渲染状态 Mixin（混入）直接复制到 1.21.8 及更早版本；旧架构没有对应渲染状态。也不要只修通用方块实体入口而忽略双箱与可疑方块随后重新覆盖光照。
- 不要只移植可变灯持久任务类而遗漏服务器 Tick（游戏刻）消费入口；任务创建、保存、载入和消费必须作为一个整体核对。
