## 5. 建筑魔杖最终规则

### 5.1 基本操作

- `Alt + 左键`：记录准星所指建筑方块；物品悬停显示已选方块。
- 左键短按：立即放置单个选择方块。
- 左键拖动：按按下位置为第一点、松开位置为第二点，生成线、面或实心体。
- `Shift + 左键`拖动：固定生成平面，平面可水平或竖直。
- `Shift + 左键`短按两次：两点决定线、面或实心体，取决于坐标跨度。
- `Ctrl + 左键`拖动：实心结构。
- `Ctrl + 左键`短按两次：中空面或中空体；一维范围不能中空，必须是普通实心线。
- 画面/体时，从第一点开始始终显示虚拟选中框。
- 松开组合键后预览冻结，不立即建筑；再次左键才确认建筑。
- `Shift + 右键`：取消当前虚拟区域。
- 手持魔杖时左键输入由模组接管，不能破坏普通方块。

### 5.2 预览微调

- `↑ ↓ ← →`：移动整个虚拟框。
- `Ctrl + ↑/↓`：调整整个虚拟框高度。
- `Shift + ↑ ↓ ← →`：移动第二点，改变范围大小和方向。
- `Shift + Ctrl + ↑/↓`：调整第二点高度。

### 5.3 放置与限制

- 空闲时准星前方最远 4 格显示候选虚拟方块，位置应与准星目标一致，不能错误高一格。
- 第一、第二点和整个虚拟框都允许悬空显示，也允许覆盖已有方块；是否可执行由最终放置条件决定。
- 创造模式：不消耗材料，可以悬空直接放置，可以替换所有方块。
- 生存模式：消耗背包中的选择方块；结构整体至少一个方块获得外部支撑；材料不足、无支撑或目标不可替换时整个预览变红，必须原子失败，一个方块也不放。
- 设置台中的平面、建筑体值没有模组人为最大值；只在 Java `int` 物理边界饱和以防整数溢出。数值过大仅提示可能卡顿，不能显示或暗示默认值是最大值。

## 6. 移动魔杖最终状态机

### 6.1 用户流程

1. 每次切换到移动魔杖，客户端查询服务端是否已有记忆。
2. 无记忆时，第一次左键记录第一点，提示“已记录第一点，请记录第二点，完成选择”，并在聊天栏追加：红石装置移动前保持静止，否则可能出错；红石开关连接状态会被清零。
3. 第一点评估完成后，仍显示第一点到准星候选点的虚拟区域，不能让虚拟方块消失。
4. 第二次左键记录第二点，立即保存第一、第二点间的所有方块和空气，提示已完成选择。
5. 保存成功后，原位置保持结构投影。绝不能恢复“第三次左键才保存选择”的旧流程。
6. 有服务端记忆时，每次切回魔杖提示 `Ctrl + 右键`显示虚拟区域。
7. `Ctrl + 右键`显示已记录结构的移动投影。
8. `↑ ↓ ← →`移动整个投影；`Ctrl + ↑/↓`调整整体高度。
9. 执行移动前，`Alt + ←/→`围绕区域中心旋转 90 度，右键方向为顺时针；方块朝向也必须随结构旋转。
10. 投影状态下按左键执行真实移动。左键在该状态必须拥有最高优先级，不能退回记录选区。
11. 成功后自动忘记选择；`Shift + 右键`可主动忘记当前记录。

### 6.2 服务端事务规则

- 记录区域包括空气，确保水和悬挂结构按原结构移动；移动完成后源位置流体、掉落物和红石变化交给原版游戏更新。
- 空气选区和没有位移的投影不得报告成功。
- 移动前保存源区域与目标区域联合快照。
- 写入过程中先按快照清空、放置并验证；失败必须恢复双方快照，只有验证成功才提示“移动完成”。
- 创造模式目标方块可直接替换；生存模式若覆盖已有方块则报错并拒绝移动。
- 基岩以及只能通过指令取得、明确禁止移动的方块不能移动。
- 移动结构视作一个整体，不产生方块掉落。
- 搬运红石前必须警告装置静止；远程开关连接状态清零。
- 搬运寻路方块必须同步更新线路节点坐标、顺序和连接边；事务失败时方块和线路一起回滚。
- 移动后若同编号寻路节点与未移动节点处于相同 `X/Z` 列，执行前拒绝整个移动。

## 9. 无线红石设备和连接器

### 9.1 设备

- 恒亮灯：红石信号开启后亮度 15、半径 14、无衰减照明。
- 16 色远程开关：普通右键改变对应颜色网络状态。
- 发射器：网络触发时六面输出强度 15。
- 感应器：允许跨颜色加入网络，是唯一可跨颜色连接的相关设备。
- 同色普通设备连接数不限；不同颜色普通设备不能直接连接。

### 9.2 连接器最终操作

- 所有连接操作均为 `Shift + 右键`，普通右键绝不能进入连接流程，因为普通右键可能操作开关。
- 第一次 `Shift + 右键`设备：记录第一个端点，连接器图标绿色闪烁/显示选中模型。
- 第二次 `Shift + 右键`设备：若不存在边则连接，已有边则断开。
- 成功连接、成功断开、同点取消、空气取消后都必须彻底清除业务选择数据和 Custom Model Data（自定义模型数据），恢复初始外观。
- 已有第一个端点时，`Shift + 右键`空气取消选择。
- 第二点无效时保留第一点，允许用户重新选择。
- 跨维度连接不允许。
- `useOn`（对方块使用）会因按住右键重复触发；服务端必须保留 6 游戏刻点击冷却，不能把一次物理点击当成一次方法调用。
- 删除连接边后，必须按删除前的完整连通分量刷新设备，确保分裂网络立刻断电；不能只依赖当前跟踪集合。

## 10. 红石能量感应器

- 不自动两两连接，必须使用连接器手动建立网络边。
- 感应器到感应器的新连接必须同 X、Y 或 Z 轴。
- 两端之间最多 10 格、至少 1 格无障碍空间；即端点坐标轴距离为 2～11。
- 中间允许空气和无碰撞的原版 `minecraft:light` 无形光源；其他阻挡方块拒绝。
- 几何规则只用于“感应器到感应器”的新增连接，不能错误套用到感应器与开关/发射器的普通连接。
- 已有感应器边必须先允许断开，再考虑当前几何是否合法，避免线路后来被遮挡后无法断开。
- 实体穿过合法感应线时输出 15。
- 感应器具有红石粉式中继：直接信号保持强度，红石粉逐级衰减 1。
- 读取邻居时必须抑制自身输出，并忽略不强于自身当前输出的红石粉回声，防止自锁。
- **正式已知限制：感应器不能作为延时开关的信号输入者，否则可能形成反馈并造成信号混乱。不要继续通过延时方向补丁尝试支持该组合，除非用户明确重新开启这项需求并接受完整重设计。**

## 11. 红石信号延时开关：唯一正确规则

这是整个项目最容易被再次改错的模块。以下规则覆盖 test8、test9、test10、test11 的所有旧推断。

### 11.1 模型几何

- 未旋转模型中，顶面箭杆从北侧开始，箭头尖端位于南侧。
- `FACING`（朝向）明确表示箭尾方向。
- `FACING.getOpposite()` 明确表示箭头方向。
- 两种模式使用带顶面箭头的模型，物品栏和放置后都必须看得到箭头。

### 11.2 输入和输出真值

- 两种模式都只有箭尾面可以输入。
- 只有箭尾面收到红石信号才启动延时计时。
- 箭尾输入面永远不输出。
- 定向模式：只从箭头面输出 15，另外四个侧面不输出也不输入。
- 五面模式：除箭尾以外的五个面全部输出 15；这五面都不能作为输入。
- 五面模式没有动态活动输入面，不扫描六面决定输入，不保存 `activeInputDirection`。

### 11.3 Minecraft 查询方向陷阱

- `getSignal`（获取信号）传入方向表示“接收方指向当前信号源”的查询方向，不是信号物理发出的方向。
- 必须先用 `RedstoneDelayFacePolicy` 把查询方向转换为物理接收面，再按上述真值表返回。
- 禁止直接写 `queriedDirection == physicalOutputDirection` 之类未经转换的判断。
- 方向测试必须逐一验证六个物理面，不能只数“有 1 个输出/有 5 个输出”。

### 11.4 延时状态

- 设置范围 0～3600 秒。
- 开启边沿和关闭边沿都完整延迟。
- 短脉冲的开启、关闭顺序和脉冲间隔必须保留。
- 修改秒数时，从当前游戏刻重新计算已有待处理边沿；不能让旧任务继续使用旧时间，也不能清空短脉冲边沿。
- 时间加法需要饱和处理，避免长整数溢出。
- 模式、延时和待处理队列随区块保存；退出重进后继续正确计时。
- 输出或模式改变时通知六个邻面重新计算，以清除旧方向残留电量；通知六面不等于六面都输出。
- 通电时切换模式不能留下旧信号。

## 12. 寻路方块和光柱

- 有 1～30 号寻路方块，同号节点组成贯穿世界高度的线路/光柱。
- 同一编号不能放在相同 `X/Z` 列，此规则保留。
- 所有人都可放置、调整和破坏，不再有所有者限制。
- 使用木镐及更好镐正常破坏并掉落。
- 取消器物品、配方、资源和注册已删除，不能恢复。
- `/pfcancel <1-30>` 删除当前维度指定编号的全部寻路方块和光柱，不掉落。
- ID 顺序重排器依次操作两个不同的同号有效方块，用于连接断线或调整顺序。
- 光柱渲染只读取已同步线路节点坐标。移动魔杖修复应更新线路数据，不能修改光柱颜色、形状、高度或渲染器来掩盖旧坐标。
- 一个维度约 200 个寻路光柱的主要负担是客户端透明渲染和节点同步；不要无需求重写渲染功能。

## 13. 模组方块放置手感

- 模组创建的所有可放置方块都走统一 `DeliberateBlockItem`（受控方块物品）或等价注册助手。
- 成功放置后统一 6 游戏刻冷却，避免比原版方块更容易连续放置。
- 魔杖、连接器和非方块工具不受该放置冷却影响。
- 新增方块时不能直接使用普通 `BlockItem` 绕过这一规则。

## 14. 模型与资源约束

- 建筑魔杖和移动魔杖当前外观已经由用户确认，不再改。
- 延时开关世界模型和物品栏模型都必须保留箭头；物品模型需要正确展示变换。
- ID 顺序重排器最终外观：灰色方头、白色中心、短棕柄、金属尾端；第一人称比例较小，不能遮挡屏幕。
- 发射器物品栏必须使用新版外观；旧版本曾因资源未同步显示旧模型。
- 连接器选中第一点后的绿色闪烁必须在 1.20.1、1.20.4、1.21.1 等旧版本保持，不能只修 1.21.4/26.x。

## 15. 八语言国际化

- Java 中所有玩家可见文字必须使用翻译键，禁止新增硬编码中文或英文显示文字。
- 默认语言：`en_us` 英语、`zh_cn` 简体中文、`zh_tw` 繁体中文、`ja_jp` 日语、`ko_kr` 韩语、`de_de` 德语、`fr_fr` 法语、`es_es` 西班牙语。
- 三个资源命名空间都维护语言文件：`building_wand`、`light`、`pathfinding_beacon`。
- 八版本共 192 个语言 JSON（8 版本 × 3 命名空间 × 8 语言）。
- 动态数字、方块名称和网络数据使用翻译参数，不得先在服务端拼成某种语言的字符串。
- `LocalizationResourcesTest` 检查语言文件存在、键集合、源码硬编码和静态翻译键引用。
- 新增文字必须同时维护八语言并检查 `%s`、`%d` 等占位符数量和顺序。
- 英语和中文是主要校对语言；其他语言为首版翻译，允许只改措辞，但必须保持键和参数完全一致。
- 根目录 `TRANSLATION_KEYS.json` 是机械迁移时的键映射参考，不是运行时资源。

## 16. 反复出错点和禁止方案

### 延时开关

- 禁止从变量名猜箭头方向；先看模型，再建立物理面真值表。
- 禁止把 `getSignal` 查询方向直接当物理输出方向。
- 禁止让五面模式动态寻找输入面或持久化活动输入面。
- 禁止把两种模式设为不同输入面；两种都固定箭尾输入。
- 禁止恢复 test11 的“箭头输入、排除箭头输出”规则。
- 禁止只改方向函数却不清理六面旧邻居电量。
- 禁止以轻量队列测试通过代替真实世界红石验证。
- 正式版不支持感应器作为延时输入；不要继续用方向补丁硬凑兼容。

### 感应器和连接器

- 禁止在放置、首次 Tick 或区块加载时重新自动配对。
- 禁止用严格 `isAir` 判断感应线，`minecraft:light` 必须允许。
- 禁止把感应器几何限制应用到所有网络连接。
- 禁止删除边后只刷新删除后的单侧或缓存集合。
- 禁止把 `useOn` 调用次数当作真实点击次数；保留冷却去重。
- 禁止只清一部分标签导致连接器选中模型残留。

### 移动魔杖

- 禁止恢复“第二点后第三次左键才保存”的旧流程。
- 禁止只修 `CAPTURE_PENDING` 或 `SELECTION_ADJUSTING` 某一个客户端阶段。
- 禁止只依赖客户端静态枚举判断服务端是否有记忆。
- 禁止投影状态的左键落入记录选区分支。
- 禁止把全空气操作、零位移操作或未经验证的写入报告成功。
- 禁止只移动寻路方块状态而不事务更新线路节点。

### GUI 和跨版本

- 禁止固定每页 10 个按钮，不考虑 GUI 缩放和逻辑高度。
- 禁止提交零宽/零高 Scissor 裁剪框。
- 禁止分别从右边定位保存与关闭按钮。
- 禁止用全局名称排序拆散编号/颜色系列。
- 禁止把 26.2 GUI API、Access Widener 或映射配置直接覆盖旧版本。
- 禁止只在一个版本修资源，其他版本继续带旧模型。

### 构建与发布

- 禁止从含历史产物的 `dist` 用宽泛 `*.jar` 上传；必须精确列出当前版本运行包和 sources 包。
- 禁止只看源码时间判断游戏加载了新包；核对模组目录文件名、版本和 SHA-256。
- 禁止让同一游戏 `mods` 目录同时存在两个可加载的 `quick-build*.jar`。
- PowerShell 5.1 不支持 `ConvertFrom-Json -AsHashtable`，不要重复采用。
- 中文路径下测试需要遵守各版本已有的 ASCII 临时测试输出方案，不要把中文路径失败归咎于用户环境。

## 17. 必须保留的回归测试

重点测试类位于每个版本 `src/test/java`：

- `DelayedSignalStateTest`：开启/关闭边沿、短脉冲、改秒数重计时、时间溢出。
- `RedstoneDelayFacePolicyTest`：模型物理面、六面输入输出和查询方向转换。
- `RedstoneFeedbackLoopTest`：红石反馈锁存。
- `RedstoneRelayPowerTest`：感应器红石中继和回声终止。
- `SensorLineRulesTest`：同轴、1～10 格、斜线和边界。
- `NetworkLinkRulesTest`：颜色和感应器连接。
- `ConnectorInteractionPolicyTest`：连接器点击状态。
- `MoveWandFlowTest`：第一点、第二点、自动保存、投影左键优先和恢复。
- `SettingsSaveFlowTest`：设置只发送一次、等待回包、权威值同步。
- `WandLimitMathTest`：无人为上限和整数饱和。
- `SettingsScreenLayoutTest`：小窗口、裁剪尺寸和按钮不重叠。
- `LocalizationResourcesTest`：八语言资源、键集合和硬编码检查。
- 寻路模块的 `RouteServiceTest` 等：整体移动节点、边、顺序、X/Z 冲突和回滚。

当前 1.0.1 每个版本完整测试为 60 项，八版本构建均成功。以后若测试数量改变，以当前源码报告为准，不要为了保持 60 删除新测试。

## 18. 游戏内交付前验证清单

### 延时开关

- 定向模式六面逐一输入，只有箭尾有效。
- 定向模式只从箭头输出。
- 五面模式六面逐一输入，只有箭尾有效。
- 五面模式除箭尾外五面全部输出。
- 开启和关闭延迟准确，短脉冲完整保留。
- 改秒数后正在等待的边沿从当前时间重新计时。
- 通电时切换模式不残留旧邻面信号。
- 保存退出并重进后计时状态正确。
- 普通红石元件和实心导体输入正常。
- 不使用感应器作为输入，只确认说明中明确警告。

### 魔杖

- 两种魔杖空闲虚拟方块位于准星目标处，不高一格，最大距离 4 格。
- 建筑第一点、第二点都可悬空预览；无支撑生存预览持续红色而不消失。
- 单方块、拖动线/面/体、Shift/Ctrl 两点模式与微调全部验证。
- 移动第一点后候选框持续显示，第二点立即保存。
- 切换物品后服务端记忆可恢复并提示。
- `Ctrl + 右键`投影后左键真实移动，不重新记录。
- 方块实体、红石粉、空气、流体、旋转朝向和失败回滚验证。
- 寻路方块移动后光柱跟随，线路功能不改变。

### 连接器、感应器和 GUI

- 一次 `Shift + 右键`不会执行两次。
- 第一端点绿色闪烁，成功/断开/取消后恢复初始外观。
- 断开后分裂网络立即停止错误触发。
- 感应器同轴 1 格和 10 格空气可连，11 格或不同轴拒绝；无形光源不阻挡。
- 设置台在多种 GUI 缩放下不虚化、不冻结、不越界、不重叠。
- 八种语言切换后不显示 `text.quick_build.*`、`item.*` 等原始翻译键。

## 19. 构建、部署和发布

在某个版本目录中使用 PowerShell：

```powershell
.\gradlew.bat clean build --no-daemon --rerun-tasks
```

每个版本构建后必须检查：

- `dist/quick-build-<版本>-mc<MC版本>-fabric.jar`
- `dist/quick-build-<版本>-mc<MC版本>-fabric-sources.jar`
- 运行 JAR 中 `fabric.mod.json` 的版本。
- 运行 JAR 中 24 个语言文件。
- Access Widener 命名空间是否符合该版本。
- `git diff --check` 和工作区状态。

八个游戏目录：

- `G:\game\mcfabric\.minecraft\versions\26.2\mods`
- `G:\game\mcfabric\.minecraft\versions\26.1.2-Fabric\mods`
- `G:\game\mcfabric\.minecraft\versions\1.21.11-Fabric\mods`
- `G:\game\mcfabric\.minecraft\versions\1.21.8-Fabric\mods`
- `G:\game\mcfabric\.minecraft\versions\1.21.4-Fabric\mods`
- `G:\game\mcfabric\.minecraft\versions\1.21.1-mtr\mods`
- `G:\game\mcfabric\.minecraft\versions\1.20.4-Fabric-mtr\mods`
- `G:\game\mcfabric\.minecraft\versions\1.20.1-Fabric-mtr\mods`

当前这些目录中的 `1.0.0` 旧包被改名为 `.jar.disabled`，Fabric 不加载；`1.0.1` 是可加载包。替换时只能操作精确的 `quick-build` 文件，不能删除其他模组。

GitHub 发布顺序：本地八版完整测试 → 八版 `dist` 运行包和源码包 → 精确检查附件名 → 提交并推送 → 新建版本标签/发行版 → 精确上传 16 个附件 → 再核对附件数量和远端提交。

## 22. 接手者的工作态度

这个项目最重要的不是继续快速打补丁，而是不要把已经修好的行为改坏。每次改动应遵循：复现 → 阅读本模块记录 → 写/确认失败测试 → 最小修改 → 模块回归 → 相关历史回归 → 发布前八版本完整验证。红石方向和移动魔杖状态机若没有逐状态、逐物理面的证据，不要修改。
