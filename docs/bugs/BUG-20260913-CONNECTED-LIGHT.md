# 2026-09-13 通光连通、模式合并与遗漏的复制灯

项目根目录：`C:/Users/quit5700/Documents/mc虚拟线路模组/快捷建筑模组`。

## 现象与根因

用户实机反馈 test1 局部白昼墙外亮带及柱子后生硬黑影，原版仍向墙后布光；复制灯未创建，独立混合选项仍在。旧方案逐格射线且排除接收方块，会把接收墙块整体判亮；直线算法无法从柱子周围绕行。原版根本没有应用遮挡过滤。遗漏副本和菜单合并属于需求执行遗漏。

## 修改

- `ConnectedLightVolume` 六邻接增量连通遍历；`DaylightOcclusion` 只在世界线程计算相邻面通光，不在渲染工作线程读取世界。满方块不进入连通集合，因此不把整个墙体判为满亮。
- `VariableLightTaskState` 原灯安装和清理共用连通范围；通路变化后重新处理真实光源。副本活动源独立保存 `legacy` 字段，安装、覆盖保护、客户端快照和禁刷怪均区分新旧行为。
- `LightBlocks`、`LightItems`、`LightBlockEntities`、`ModItemGroup` 注册副本；使用单独资源模型、纹理、掉落、配方和八语言名称。
- 菜单同步增加副本标记；`VariableLightPresentation` 区分原灯两模式与副本三模式。保留 HYBRID（混合）旧序号作为原版增亮状态，不破坏旧保存配置。
- 原版满足逐格布光时固定间隔为 1，副本保留原 1～7 设置。门闭合会阻断路径，打开后重算；玻璃通过；半砖、楼梯、活板门使用相邻面的形状判断。

## 错误记录与避免重复

- 首次编译调用 `Direction.fromDelta` 失败：26.2 没有此方法。改为六个确定方向的坐标比较；旧调用已尝试失败。
- 不能用所有方块的原始遮挡形状对象差异触发重算：无形光源与空气可能默认形状不同但均不遮挡。只检查有效遮挡/实体形状变化，避免布光使自身计算反复失效。
- test1 直线射线作为单元算法仍保留测试，但不再作为实际局部白昼覆盖算法。不要再用“排除目标墙块”的射线结果给整个墙体强制满亮。
