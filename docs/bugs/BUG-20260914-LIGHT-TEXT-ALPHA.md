# 照明设置文字透明

当前项目根目录：C:/Users/quit5700/Documents/mc虚拟线路模组/快捷建筑模组。类型：26.2 渲染接口适配／界面可见性。状态：test7 代码与自动回归完成，实际画面待验收。

## 现象与根因

用户切换两点真实照明后看不到卡顿提示。核对已安装 test6，中文语言资源确实包含这句话；源码位于选择按钮下方，传入颜色 0xFFB040。检查当前 Minecraft（我的世界）26.2 的 GuiGraphicsExtractor.text（文字绘制）编译接口，ARGB.alpha（提取透明度）等于 0 时直接返回。因此该六位颜色被当作 0x00FFB040，完全透明，而不是不透明橙色。同页面其他手工绘制文字也使用了六位颜色。

## 修改

mc26.2/src/main/java/cn/quit5700/light/client/VariableConstantLightScreen.java：将所有显式六位文字颜色补为 FF 开头的八位颜色，包括标题、警告、范围说明、供电状态与局部白昼说明，不改模式条件或已批准布局。

新增 mc26.2/src/test/java/cn/quit5700/light/logic/LightScreenColorTest.java：使用 UTF-8 读取实际页面源码，检查所有显式颜色不透明度为 255。修复前该测试失败，修复后通过，未弱化旧测试。

## 验证及限制

颜色定向测试先失败后通过；最终完整构建成功，115 项测试、0 失败、0 错误。此回归证明颜色参数符合绘制接口，不是实际像素截图测试。仍需打开游戏确认文字位置、换行和显示。

已尝试失败：使用 0xFFB040 等六位 RGB（红绿蓝）颜色传给要求 ARGB 的文字接口。后续 26.2 界面颜色默认显式使用不透明度，不得再把语言键存在、编译成功当作文字已可见。

排查工具注意：PowerShell（命令行）调用带点号的 Java 系统参数时要整体引号包裹；javap（类接口查看工具）在缓存归档退出时报访问被拒绝时，不以退出码代替实际已输出接口证据，不修改归档权限。项目编译及文本读写继续显式 UTF-8。
