# 区域替换受保护材料被附着物支撑保护阻碍

当前项目根目录：C:/Users/quit5700/Documents/mc虚拟线路模组/快捷建筑模组。
类型：核心逻辑、邻居更新、自然支撑与掉落。
用户现象：区域替换选择箱子后部分原木保留。用户确认受保护材料可替换普通方块；周围红石、火把等若替换后的方块能承托则保留，否则正常掉落。普通材料保持现有支撑保护，区域已有受保护方块仍跳过，实体保护不改。
根因：ReplacementRules.protectedPosition只有新火把豁免附着物支撑检查，箱子等仍拦截；上方受保护方块也参与支撑检查，存在任务顺序相关风险。原支撑测试曾规定箱子阻挡，与用户本次新规则不同。不能删除实体保护或直接放行已有容器。
修复前复现：26.2保留test8生产代码，新增真实任务回归，原54项通过，箱子替换承托火把的钻石块场景失败；修复前完整日志保留versions/1.1.8-test9/修复前复现.log。垂直箱子连续替换场景原代码通过，不能声称在该特定顺序复现了箱子自阻挡。
修改文件：四版ReplacementRules.java只将TorchBlock单独豁免扩展为已有protectedMaterial分类；StructurePlacement.java仅箱子natural特殊分支补原版updateNeighbourShapes，保证失去支撑的附着物有形状更新。旧QUIET写入后仅updateNeighborsAt不足以保证所有依赖updateShape的附着物自然检查。本次不改保护清单、普通材料支撑循环、实体分支、连接更新、箱子SINGLE设置、其他法杖与资源。
测试：新增三个实际服务器案例，六类附着物（普通火把、红石火把、红石粉、中继器、压力板、灯笼）分别验证熔炉替换后保留、箱子替换后不悬空；箱子竖列完整替换且不合并。原箱子材料应阻挡红石/按钮的两条预期依据明确新需求调整为允许，其余旧正确预期不变，原实体和普通材料火把支撑保护继续通过。完整测试结果见下。
已尝试失败：仅豁免TorchBlock的旧规则无法处理箱子等受保护材料；不能据普通材料支撑保护通过断言受保护材料替换正确。不得强行保留无法承托的附着物，不得让容器/红石等源方块被直接替换。
防重复：必须区分源方块保护和所选材料分类，分别测试实际任务两个方向；不同版本独立编译原版邻居更新接口和验证，不能凭单版推断其他版本。其他版本遵照测试一版、检查修正一版，不提前更新。
