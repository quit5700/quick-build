# 26.3测试12：建筑生成箱与蓝图法杖

用户授权先处理26.3：建筑法杖生存范围建造改用既有生成箱；辅助法杖更名为蓝图法杖。其他九版本批不改，不沿用上一批一次关机授权。

设计：保留建筑引擎的选区、替换过滤、自然掉落、成对结构、耐久和分批游标；生成箱复用蓝图任务的投料、退料、权限和保护。范围任务材料计数标明预计上限，不展开全体方块计划；按实际建造扣料，允许分批供料，完成/取消/工具损坏退还未用余料。创造及单格模式保留原行为。旧持久任务在首次需要生存供料时接入箱子；内部旧任务执行接口保留以验证既有核心规则，玩家新请求均通过生成箱入口。

风险重点：存档关联恢复、箱子被移除、重复取消/退料、跨维度、材料不足、已有同材/受保护方块、多格方块一件计料及耐久损坏。玩家文字全部翻译键，八语言同步；内部物品ID不变以兼容旧存档。

最终验证：302项单元测试、60项世界回归、60项配方检查、6250项实际客户端检查通过；照明prepare/verify/persist（准备/重载验证/再保存）通过。八语言键集合及占位符一致。用户游玩验收仍待完成。


## 本批失败分类与处理

Java语法/脚本替换问题：首次生成脚本过宽的字符串替换误将supply、bank参数加入完成提示，引起两个未定义变量编译错误；只修正完成提示参数，保存数据的data方法保留新增字段。已尝试失败：复用宽泛字符串替换修改不同签名；下次只定位精确调用。日志：首次编译.log、构建2.log。

版本接口问题：独立客户端探针使用Blocks.RED_BED常量，在26.3不存在；改用本项目既有成功方法，从原生注册表读取minecraft:red_bed。只影响探针，不影响生产代码。已尝试失败：直接使用旧版床常量。日志：实际客户端验证_1.log；后续实际客户端验证通过。

测试契约变化：三项旧火把入口回归使用没有网络连接的模拟玩家，仍期待确认后自动扣背包；本批玩家入口已改用生成箱，箱同步无法发送且不再自动扣背包，因此任务等待。修正测试分层：保留全部选材、警告、旧过滤清除和生存放置断言，新增箱任务入口断言；然后通过原低层接口验证同一选材及过滤的精确生存扣料。实际客户端另验证真实玩家选择范围、创建任务、投料、取消和重进。不是放宽正确预期或跳过测试。新增旧存档迁移回归，最终场景数由59增至60。保留世界旧供料预期失败.log。禁止将构建退出成功当作世界回归成功，交付必须核对Q5_CASE_FAIL及最终标记。

涉及生产文件：BuildTaskState.java、BuildWandServer.java、BuildSupplyBudget.java、AuxServer.java、AuxScreens.java及八语言资源。新增BuildSupplyBudgetTest.java；世界测试追加迁移及适配新供料契约。没有改变移动、删除、照明及既有蓝图计划执行核心，最终回归实际结果见交付核验。

新增待确认需求：用户询问信标塔取消底座材料限制，已建议允许蓝图支持的任意方块，并说明其他材料不会激活原版信标。按用户要求等待“处理吧”；本批不实施。
