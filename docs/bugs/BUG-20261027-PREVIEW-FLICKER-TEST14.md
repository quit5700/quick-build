## 复现、假设及根因

类型：客户端透明预览深度冲突、任务状态与材料账本。AuxRendererDepthTest通过代理真实VertexConsumer捕获AuxRenderer.face提交的20个顶点，修改前明确失败：填充和边线深度相同；同一函数的填充面也与材质模型原表面重合。这是可复现的深度冲突，不依赖重写材质。独立客户端按两个25格塔重放六个相邻视角，橙色无材料、绿色绿宝石材质与用户截图对应；前后截图均保留。

已展示并测试的假设：共面填充/边线争抢深度、材质/彩色面重叠、移动缓存清空。前两项由真实顶点检查证实。六个视角观测到完整网格3852个面，前后数量相同；该场景没有以数量下降证明缓存故障，不把它冒充已复现的另一根因。缓存改动作为稳定措施：固定增量构建的裁剪中心，在完整新网格准备好后切换，避免移动过程中替换为半成品。

最小修改：彩色面沿法向外移0.003格，边线再外移0.003格，模型保持原位；六方向与不同相机的真实提交顶点分别检查模型/填充和填充/边线之间有深度间隔。没有修改材质或形状，没有增加持续调试日志。原错误模式已经由针对性的实际调用回归覆盖。

## 新箱流程的失败记录

实际客户端验证_1失败于building_box_second_bed_completes。根因是新增加的启动门禁会检查Running，而旧分批供料逻辑在最后一件材料用完时设Running=false；多格游标还要跳过组内第二格，导致已经生成的床无法完成任务。修复：收齐材料后启动的任务不因余额恰好耗尽而提前停止，保持游标继续收尾；实际放置仍逐件核验与扣费。存量部分供料任务及游戏模式变化通过buildRunning统一重查，生存余额不足仍暂停。已尝试失败：在新整体启动门禁下继续沿用旧“余额归零立即暂停”行为，不能再次采用。对应失败日志保留，不忽略失败或放宽完成断言。

修改生产文件：AuxRenderer.java、BuildTaskState.java、BuildWandServer.java、AuxServer.java及八语言提示。新增AuxRendererDepthTest；客户端探针按已确认新需求更新部分供料与创造入口预期，保留真实取消、精确扣料、退料、成组方块、损坏、重进、信标和中文文件原有正确预期，并增加模式变化与真实创造按钮点击。
