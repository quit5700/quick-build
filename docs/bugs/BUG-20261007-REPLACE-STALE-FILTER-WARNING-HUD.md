# 区域替换旧筛选残留、材料选择被误作筛选及提示遮挡

项目根目录：C:/Users/quit5700/Documents/mc虚拟线路模组/快捷建筑模组。
类型：持久状态、材料选择、客户端服务端交互、提示布局。
状态：1.1.8-test6四版自动验证及安装完成，客户端新显示待实机验收，未转正式版。

现象：用户26.1.2只选择地面火把，替换钻石块显示完成但替换0块；1.21.11和1.21.8要求一并处理。Shift+右键选择时，红色保护警告覆盖浅蓝色选择确认，四版（含26.2）均需检查。

证据与根因：读取本项目对应测试存档，建筑法杖保存SelectedBlock=minecraft:torch和Q5ReplaceTarget=minecraft:oak_log。这只证明法杖存在旧筛选，不能声称用户此次主动选择橡木原木。代码pickMaterial在材料非空时把任何新选择记成替换目标，同一火把再次选择也变成火把筛选；材料为空时第一次选择不清除旧筛选。重新进入区域模式也保留旧筛选。旧测试直接创建无筛选新任务，未覆盖保存过的法杖及完整选择操作。

提示根因：WandActions.selectBlock发送浅蓝色普通提示后，warnMultiple又sendOverlayMessage警告；原版只有一个此类显示槽，后发红字替换浅蓝文字，并非异常崩溃。

修复前回归：在26.1.2实际独立服务器用test5生产代码复现五项新增失败，原49项保持。完整日志versions/1.1.8-test6/修复前复现_mc26.1.2.log。保留已验收test5原目录及安装包，不改玩家数据来掩盖代码问题。

修复：进入区域替换时清空旧筛选，保留全模式材料。区域模式初选材料、重选当前材料或选择本身受保护而不能作为有效替换目标的方块时，设为建造材料并清空旧筛选；其他可替换方块继续作为第二种筛选。切换手持物仍保留当前材料、明确选择的筛选和两点选区。被替换方块确认也使用浅蓝色提示。

显示：BuildNetworking.State增加独立warning翻译键字段，随权威请求回应传递，客户端仍校验维度、法杖、槽位和顺序。BuildWarningHud在原版提示下方独立画红字，原提示位置不动；6秒显示，退出法杖/模式/世界或断开连接时清除，不覆盖浅蓝提示。窄窗口长语言最多显示两行，溢出分段轮播，避免覆盖物品栏。系统警告记录保留。26.x用GuiGraphicsExtractor.text，1.21.x用GuiGraphics.drawString，使用本地Fabric API确认的HudElementRegistry和OVERLAY_MESSAGE锚点，禁止混用26.x与旧接口。

修改文件：四版server/BuildWandServer.java、network/BuildNetworking.java、client/BuildWandClient.java、新client/BuildWarningHud.java、smoke/server/WandSmokeChecks.java及必要版本元数据。保留test5文字、保护清单、自然掉落、实体保护、其他法杖行为、配方、耐久和模型。
