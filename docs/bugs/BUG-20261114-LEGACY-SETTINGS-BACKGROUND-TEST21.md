# 设置台正文被背景覆盖或模糊

当前项目根目录为 C:/Users/quit5700/Documents/mc虚拟线路模组/快捷建筑模组。

## 现象和分类

客户端绘制顺序及版本适配问题。用户提供的 1.21.4 设置台截图中，左侧按钮清晰，右侧说明和图标模糊。检查范围按用户补充扩展到 1.21.1、1.20.4、1.20.1。

## 根因

测试19设置台的 WandSettingsScreen.render 先绘制面板、文字及物品图标，最后调用 Screen.render。1.21.4、1.21.1 和 1.20.4 的原生 Screen.render 会先调用 renderBackground，再绘制按钮。两个 1.21 版本会因此在内容之后执行模糊。1.20.4 会在内容之后画背景，造成遮挡或变暗。1.20.1 的 Screen.render 直接画控件，没有相同的背景调用。

本项目 BUG-20261008-TOOLTIP-SCREEN-BLUR.md 曾记录同类错误，但测试19设置台丢失了该修正。既有检查主要覆盖布局和功能，缺少设置台原生绘制调用顺序的自动回归。

## 修改范围和修复方式

仅在测试21的 mc1.21.4、mc1.21.1、mc1.20.4 中调整客户端 WandSettingsScreen.java。在 render 开始显式调用 super.renderBackground，再画自定义内容。覆盖后续原生 renderBackground 回调为空，最后保留 super.render 绘制控件。1.20.1 仅检查，不生成无改动测试包。

新增三版 SettingsBackgroundOrderTest.java，读取实际原生 Screen 和设置台编译字节码，验证原生背景调用存在、晚期覆盖方法不再绘制，以及显式背景先于第一处自定义图形调用。新增 scripts/SettingsBlurProbe_test21.java、scripts/probe_settings_blur_test21.py 和 scripts/probe_settings_interaction_test21.py，探针只注入独立验证副本。

版本号为 1.1.9-test21。工作版本通过项目 versions/1.1.9-test21 目录链接指向 H:/CodexWork/快捷建筑_设置台修复_20261114/版本/1.1.9-test21。构建、探针和新缓存均在 H 盘。逐版最终软件、源码和依赖信息随交接目录保存。

## 验证

修改前 1.21.4 的 104 次、1.21.1 的 103 次、1.20.4 的 101 次背景调用全部发生在内容之后。三版均保留实际截图与探针计数。1.20.1 的原生背景回调计数为零，截图可直接核对。针对性自动回归在修改前失败，未修改原预期。

1.21.4 修改后截图确认说明、图标和面板清晰，背景晚绘制计数为零，325 项完整单元测试通过。其他最终结果与安装状态以各版交付核验.json 为准。独立客户端未加载用户实例中的额外模组，游戏原存档与整合环境仍待用户实测。

## 已尝试失败和防重复

- 已尝试失败。直接以中文路径作为 Gradle 用户缓存目录，Gradle 测试工作进程无法加载 GradleWorkerMain。主项目仍使用中文路径，将 Gradle 专用缓存用 H 盘英文目录链接访问，解决辅助进程启动。不能把这类问题归因于用户环境。
- 已尝试失败。测试临时目录通过链接访问，蓝图中文路径测试预期与真实路径规范化结果不同。改用 H:/CodexWork/q5-settings-runtime-tmp 实体临时目录，保留原测试的中文文件名和断言。
- 已尝试失败。1.20.1 初次探针使用较新版的 isGameLoadFinished 接口，编译失败。按现有适配脚本使用无覆盖层且标题画面就绪条件，运行采用 Java 17。
- 后续版本同步必须对设置台单独检查背景调用，不能只检查辅助蓝图弹窗，也不能仅以按钮清晰判断整个界面正常。
