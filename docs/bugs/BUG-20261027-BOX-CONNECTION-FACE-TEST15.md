# 26.3测试15：生成箱可达位置与固定连接面旋转

项目根目录：C:/Users/quit5700/Documents/mc虚拟线路模组/快捷建筑模组。基线1.1.9-test14，仅26.3；本轮独立1.1.9-test15。2026-10-27用户授权“处理吧”。

类型：生成箱位置搜索、客户端旋转交互。

现象：用户确认建筑范围后找不到生成箱；蓝图旋转时希望最初面对的面始终朝向自己，整个长方体保持尺寸与内容相对关系。

证据：原游戏latest.log两次记录箱子坐标，不能认定所有确认事件均失败。将原createBuildBox同高水平搜索提取到真实调用的BuildBoxPlacement后，新回归3项中2项失败：宽浅范围内部玩家得到远角箱、同高度无空位时漏掉近处上下空位。原连接面算法固定取第一项局部负Z面，短轴侧面点击回归失败；优先绕X轴的水平180度回转使上下颠倒，针对性回归失败。修改前日志保存在版本目录。

修复：优先按距离搜索玩家附近三维空位，仍排除选区、越界、权限不允许、已占用箱位及玩家碰撞体；没有近位才保留原外部搜索兜底。蓝图连接时根据真实射线与命中体素记录世界面法向，之后用该面计算整组选区共同旋转；水平转向优先绕Y轴，避免180度翻转上下。保留固定中心方块支点、90度步进、平移、取消及服务端验证。

涉及文件：测试15的BuildBoxPlacement.java、AuxServer.java、AuxFacing.java、AuxClient.java、两个新增回归测试、gradle.properties及交付文档；其余调整以最终源码差异清单为准。

已尝试失败：仅同高度扩大水平半径不能解决附近上下空位被漏掉；固定取第一项预设负Z面不能满足实际连接面；水平180度优先绕X轴会产生不必要上下翻转。禁止后续恢复这些已证实错误模式。

验证进行中：修改前回归已失败，修改后需执行定向、完整单元、世界与独立客户端检查。用户原存档未写入，不能把自动通过视为用户验收。

下次避免：放箱检查可达性及三维候选，不仅检查setBlock成功；旋转输入检查实际连接面，不能仅证明矩阵正交。不要改写本地尺寸、形状、微调删除、材料或蓝图内容来模拟旋转。
