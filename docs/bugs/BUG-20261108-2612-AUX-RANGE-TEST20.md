# 26.1.2 生成范围和蓝图选点未绘制

- 类型：版本适配 / 客户端渲染阶段回归。
- 现象：确认建筑法杖选区后生成箱存在，但建筑范围不可见。蓝图法杖的第一点、第二点和选区边框也不可见。
- 根因：`AuxRenderer` 在半透明地形绘制前回调中提交绘制节点。26.1.2 这个时点已晚于特征绘制器读取本帧节点。选区的数据已同步，节点也进入了队列，但绘制回调未运行。
- 变更：`versions/1.1.9-test20/mc26.1.2/src/client/java/cn/quit5700/buildingwand/aux/AuxRenderer.java` 改在收集绘制节点阶段注册。复用同版 `BuildBoxRenderer` 等已验证的注册时机。修改范围限于客户端绘制入口。
- 回归：`scripts/probe_range_test20.py` 与 `scripts/RangeRenderProbe_test20.java` 分别在独立的测试19与测试20客户端创建同一个生成箱任务，注入蓝图选点，然后检查实际绘制回调输出四种颜色并保存截图。测试19已复现四项均未绘制。构建通过，324 项单元测试无失败。其余结果见版本目录内的交付核验。
- 已尝试失败：仅统计准备好的网格或队列提交数量，无法识别节点未被绘制器消费。防回归必须检查绘制回调或最终像素。独立客户端初次运行缺少 Fabric API 整包而被加载器拒绝，复测采用同一实例的 API 整包。
- 跨版本：核对其余九版注册方式。26.2、26.3 与各自建筑、删除和预览渲染器采用相同事件。早期版本用各自对应接口。此次仅交付复现了问题的 26.1.2。
- 相关记录：`BUG-20261005-2612-RANGE-SUBMIT-PHASE.md`。

- 实机正向验证：测试20真实建筑任务等待生成时，蓝色建筑范围与生成箱同时可见。蓝图第一点、第二点和白色完整边框同屏可见。测试用例直接设定蓝图端点，覆盖绘制，不覆盖鼠标选点输入。早期探针只创建独立生成箱，服务端会按设计移除无建筑任务的箱子。最终探针通过建筑任务入口创建箱子，并在持有蓝图法杖后稳定设置端点。

- 同一最终探针对照：测试19四项绘制均为假；测试20四项均为真。两版截图和日志随交付保留。

- 安装：用户退出游戏后已替换 26.1.2 的测试运行包，校验 SHA-256 一致，旧包保留为禁用备份。
