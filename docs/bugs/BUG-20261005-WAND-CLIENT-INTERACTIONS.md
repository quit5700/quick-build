# 1.21.11法杖交互、范围框及模型跨版本修复

当前项目根目录：C:/Users/quit5700/Documents/mc虚拟线路模组/快捷建筑模组。类型：客户端渲染、输入/状态同步、模型资源、版本接口适配。版本：1.1.6，八版本自动验证通过，等待玩家客户端验收。

现象：ID顺序重排器图标错误；建筑/删除两点范围框与真实操作区域错位；刚切建筑法杖偶发无响应；区域替换用箱子缺提醒；第二种被替换材料选不上。用户提供三张预览/确认范围/实际结果图，并反馈1.21.11。

根因与范围：七个非26.2版本仍为旧平面重排器JSON模型，26.2已为26部件立体模型；此前仅同步PNG和开关JSON，遗漏其他物品模型。八版本范围框使用反射查相机，旧版运行包方法命名会重映射而反射字符串不会，失败后回退脚部位置，导致框与使用真相机的光标预览错位。八版本BuildWandClient等待QUERY时丢弃所有点击，并将边沿记为已消费；拒收/丢失回包无查询恢复，切回物品才恢复。Fabric末尾tick的自定义请求可早于原版手持槽位包，需先同步手持。服务端已有双材料逻辑，但旧客户端点击丢弃、模式/材料回包不完整，直接调用pickMaterial的旧独立测试绕过真实请求/回包。箱子保护后不可再替换仅写在说明台，未有操作提醒。

修改文件：各版本BuildBoxRenderer、DeleteBoxRenderer、WandPreviewRenderer、BuildWandClient、BuildRequestQueue、BuildNetworking、BuildWandData、BuildWandServer、重排器JSON模型、八语言、WandInteractionRegressionTest、BuildRequestQueueTest、WandSmokeChecks及版本依赖说明。

修复：相机采用各版编译期绑定接口/渲染上下文，禁止反射和脚部回退；七版重排器同步26.2基准，不改变26.2已正确模型。点击串行队列保留首次查询期间及快速两次选材点击；超时指数退避仅QUERY同步，不重复删除/建造确认，切物品清除待发点击，保留服务端材料/选区。先发送原版手持槽位包，再发带法杖ID与槽位的请求，服务端拒绝跨手持执行。回包带权威模式、建造材料和目标类型，客户端确认当前手持后同步到同把法杖。区域替换选箱子等方块实体材料、切入模式和第二点确认时红字提醒，仍允许左键继续、右键取消，原保护规则不变。

已尝试失败：26.1.2照搬26.2的mainCamera方法名，编译明确不存在；核对实际类接口，26.1.2用getMainCamera，26.2用mainCamera，1.21.11取context.worldState().cameraRenderState.pos，较旧版本用context.camera()对应API。不重新使用反射猜测名称。失败日志已保留。

验证：1.21.11原模型和范围框新增回归先在旧代码失败，修复后通过；9项实际客户端使用的点击队列测试通过。1.21.11共31项独立世界测试通过，新增真实BuildWandServer.handle请求、连续双材料及客户端权威快照、手持ID/槽位拒绝及恢复、箱子提醒、真实请求/回包编码往返。八版本完整构建通过，1564项自动测试和248项独立世界回归通过；上一轮六灯保存、迁移重载及再次重载检查共24次启动全部通过。不以服务器测试声称实际画面已实机验收。

避免重复：不能只同步PNG；资源核验必须含物品JSON模型。普通点预览与区域框必须用相同相机位置。不得在等待回包时吞点击并永久卡pending；不得重试已发出的建造确认。必须测真实请求入口，不能只测材料工具函数。局域网客户端与服务端须一起更新为1.1.6，本轮扩展了请求/回包字段。

版本接口补充：已尝试失败，1.21.4相机position()不存在；1.21.4/1.21.1和1.20系列是getPosition()，1.21.8是position()。对照各目标已有单点渲染器的实际相机表达式，同版本区域框复用同一接口；避免只按大版本猜方法名，失败日志保留。

客户端维度初始化补充：原控制器的END_CLIENT_TICK先发QUERY，随后BuildWandClient注册的END_CLIENT_TICK才初始化维度并clear状态，第一次持杖的请求状态可能被清掉。修复把world初始化移到处理手持输入之前，维度变化仍清选区视图，服务器按法杖保存的数据不改。快速输入测试与生产客户端共享同一个BuildRequestQueue实现，不是单独镜像。
